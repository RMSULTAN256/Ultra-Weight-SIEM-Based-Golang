TAKSONOMI & ARSITEKTUR 5 GENERASI SIEM

Perbandingan Alur Data, Fokus Aktivitas Teknis, Beban Sumber Daya, dan Posisi Proyek Mini-SIEM Golang Anda

1. Conventional Database SIEM (Gen-1: Post-Processing Relational)

Contoh: OSSIM, Early ArcSight, Legacy MySQL/PostgreSQL Log Warehousing
Gen-1: Batch Audit

Fokus Aktivitas Utama

Sentralisasi log untuk kepatuhan audit (compliance), penyimpanan riwayat audit di tabel relasional, dan eksekusi kueri agregasi terjadwal (cron job).

Karakteristik & Bottleneck

  • Bottleneck: Disk I/O tinggi saat jutaan log di-INSERT.
  • Latensi: Menit hingga jam (post-processing query).
  • RAM: 2 - 4 GB (bergantung pada DBMS).

Batasan untuk Real-Time

Jika terjadi serangan brute-force berkecepatan tinggi, kueri database akan lambat (*query backlog*) dan penyerang sudah berhasil masuk sebelum alert muncul.

2. Big Data & Inverted Index SIEM (Gen-2: Search-Centric Analytics)

Contoh: Elasticsearch Logstash Kibana (ELK Stack), Splunk Enterprise Security
Gen-2: Index & Search

Fokus Aktivitas Utama

Pencarian teks bebas (*free-text search*) super cepat menggunakan indeks Lucene terbalik (*inverted index*), visualisasi chart masif, dan investigasi forensik manual.

Karakteristik & Bottleneck

  • RAM: 4 - 16 GB (membutuhkan JVM Java Heap besar).
  • Storage: Indeks data memakan 120-150% dari ukuran log asli.
  • Aturan: Proprietary (KQL / SPL).

Batasan untuk Resource Terbatas

Sangat boros RAM dan CPU. Tidak dapat dijalankan pada edge router, container kecil, atau server tunggal berspesifikasi rendah tanpa risiko Out-Of-Memory (OOM).

3. Distributed Cloud Streaming SIEM (Gen-3: Complex Event Processing)

Contoh: Apache Kafka + Apache Flink + Datadog Cloud SIEM / AWS OpenSearch
Gen-3: Stream Engine

Fokus Aktivitas Utama

Penanganan jutaan EPS secara horizontal terdistribusi, event-driven streaming, dan korelasi multi-region lintas layanan cloud.

Karakteristik & Bottleneck

  • Throughput: Sangat masif (10.000+ EPS).
  • Kompleksitas: Memerlukan tim DevOps ahli (Zookeeper, Kafka nodes, Flink cluster).
  • Biaya: Sangat mahal untuk organisasi kecil / server lokal.

Relevansi dengan Tugas Akhir

Membuktikan keunggulan arsitektur streaming pipeline, tetapi stack-nya terlalu raksasa untuk di-deploy di laptop atau server mandiri.

4. AI / UEBA & Autonomous SOAR SIEM (Gen-4: Behavioral & Machine Learning)

Contoh: Exabeam UEBA, Securonix, Wazuh ML Anomaly, Jurnal 7 (LAC) & Jurnal 14 (RL SOAR)
Gen-4: AI & Behavioral

Fokus Aktivitas Utama

Mendeteksi anomali perilaku halus (insider threat, pencurian data di luar jam kerja) tanpa aturan statis, serta mengeksekusi aksi respon insiden adaptif.

Karakteristik & Bottleneck

  • Kebutuhan Data: Perlu baseline historis bersih berminggu-minggu.
  • Sifat Black-Box: Sering memicu False Positive saat ada perubahan pola kerja wajar.
  • Komputasi: Membutuhkan GPU / CPU tinggi untuk inferensi model.

Pelajaran untuk TA

AI/ML cocok sebagai asisten analisis insiden (tier hilir), namun berisiko jika dijadikan penentu tunggal deteksi utama tanpa filter aturan deterministik.

5. Lightweight In-Memory & Open-Standard SIEM (Gen-5: Proyek Tugas Akhir Anda)

Mini-SIEM Native Golang: Forwarder-Collector + Upstream Threat Intel + In-Memory Sliding Window + Sigma Engine
Proyek Anda: Sub-Second & <100MB RAM

Fokus Aktivitas Utama

Deteksi Dini Berkecepatan Tinggi (Sub-Detik): Aliran log dinormalisasi, diperkaya info ancaman IP di memori, dan dievaluasi dengan aturan Sigma YAML menggunakan Sliding Window Buffer sebelum data ditulis ke disk.

Keunggulan Rekayasa TA Anda

  • Footprint: Sangat hemat memori (<100 MB RAM).
  • Zero Dependency: Tanpa Elasticsearch, Kafka, atau Java runtime.
  • Standar Terbuka: Mengadopsi Sigma YAML & MITRE ATT&CK.

Pengisian Gap Ilmiah (Bab 2)

Menggabungkan kecepatan korelasi in-memory (Jurnal 1), akurasi sliding window time-series (Jurnal 2), pengayaan upstream CTI (Jurnal 5), dan format aturan standar terbuka (Jurnal 4).
