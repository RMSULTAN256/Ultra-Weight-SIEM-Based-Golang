1. Wazuh Open-Source SIEM: Arsitektur Daemon & Pipeline XML Engine

Sumber: Wazuh Inc. Official Architecture & C/C++ Codebase (SIEM Open-Source Standar Industri)
Wazuh De-Facto Standard
4 GB - 8 GB RAM Wazuh Dashboard (Kibana OpenSearch Fork) • Node.js runtime web application (Port :443) • Communicates with Wazuh REST API (:55000)

Detail Engine Analysisd Wazuh

  • Single-Threaded Bottleneck: Daemon analysisd bekerja secara sekuensial; saat terjadi flood puluhan ribu EPS, antrean queue/ossec menumpuk (*backpressure*).
  • Aturan XML Hierarkis: Rule anak mewarisi rule induk (misal: <if_sid>5700</if_sid> untuk deteksi brute force bertingkat).

Komparasi Langsung dengan Mini-SIEM Go Anda

  • Bahasa: Wazuh (C murni + Python API + Java Indexer + Node.js UI) vs Proyek Anda (100% Native Golang Single Binary).
  • Resource Footprint: Wazuh butuh 4-8 GB RAM vs Mini-SIEM Anda <80 MB RAM.
  • Aturan: Wazuh memakai XML proprietary kaku vs Mini-SIEM Anda memakai Sigma YAML terbuka.

Contoh Kode Aturan Asli Wazuh

<!-- Wazuh SSH Brute Force XML --> <rule id="5712" level="10" frequency="8" timeframe="120"> <if_matched_sid>5710</if_matched_sid> <same_source_ip /> <description>SSHD brute force attack.</description> <mitre><id>T1110</id></mitre> </rule>

2. Simple Event Correlator (SEC): Stateful Context Memory & Sliding Window

Sumber: Risto Vaarandi (Jurnal 1 MDPI Sensors 2024 & IEEE NOMS Benchmark)
Pionir Stateful Correlation
pattern=Failed password for (\S+) from (\S+) Extract match variables: $1 = Username, $2 = SourceIP Mode: SingleWithThreshold Key: SSH_FAIL_$2 Window: 300 detik Thresh: 5 kali event Timer resets dynamically Mode: PairWithWindow Event A: Login Gagal Buka window W = 10m Event B: Login Sukses Picu: Compromised Account! IN-MEMORY CONTEXT & ACTIONS Perl Heap Context Hash Table: • $context{"SSH_FAIL_103.145.22.8"} = { count: 5, exp: 1729000 } • Sliding window garbage collected saat timer exp tercapai • Zero disk persistence: Log hilang jika proses crash Action Execution (Spawn Child Process): • action=pipe '%s' /usr/bin/mail -s 'Alert' admin@org • action=shellexec /sbin/iptables -A INPUT -s %2 -j DROP Fork/Exec overhead berat jika ribuan aksi dipicu

Prinsip Desain SEC

  • SEC dirancang tanpa database relasional: murni menggunakan state table di memori Perl.
  • Menggunakan struktur timer dinamis untuk membersihkan memori saat event telah melewati batas waktu window.

Yang Kita Adopsi di Mini-SIEM Go

  • Pola SingleWithThreshold diadopsi menjadi buffer sync.Map berstempel waktu []time.Time.
  • Pola PairWithWindow diadopsi untuk mendeteksi login gagal beruntun yang disusul oleh login sukses dari IP asing.

Peningkatan di Proyek TA Anda

SEC memakai single-thread Perl yang memicu latensi tinggi saat volume log melonjak (terbukti 21x lebih lambat di Jurnal 1 MDPI). Golang menggunakan Goroutines non-blocking dan format Sigma YAML standar industri.

3. Splunk Enterprise Security: Ingestion & Risk-Based Alerting (RBA) Pipeline

Sumber: Splunk ES Reference & Jurnal 13 (Fraunhofer FKIE / Uetz et al., 2026)
Enterprise Splunk Framework
index=risk (Tanpa alarm) 2. Risk Modifiers & Attribution • Asset Priority: Domain Controller (+40) • Identity Risk: VIP User (+30) • Threat Object: Malicious Datacenter IP (+30) 3. Risk Incident Rule (Aggregation Threshold) `index=risk | stats sum(risk_score) as total_risk, values(threat_object) by risk_object | where total_risk >= 100` ESCALATE TO NOTABLE EVENT (index=notable) -> Triage di Incident Review Dashboard

Kehebatan Alur RBA Splunk

  • Alih-alih membuat 1 alert setiap kali ada gagal login (yang membuat analis kebanjiran ribuan alert palsu), event hanya dicatat sebagai poin risiko ke index=risk.
  • Alert baru dibuat saat ada entitas (IP atau User) yang mengumpulkan skor risiko $\ge 100$ dalam 24 jam.

Adopsi pada Mini-SIEM Go Anda

  • Modul evaluasi menghitung skor risiko gabungan 5 faktor (RBA): Level Rule + Akumulasi Frekuensi + Kelangkaan Rule + Modifikasi Reputasi IP (Hosting/Tor).
  • Hanya insiden dengan skor ambang tinggi yang dikirim ke respon mitigasi otomatis.

Kelemahan Splunk yang Diatasi

Splunk sangat mahal (lisensi dihitung per GB/hari) dan kueri SPL terjadwal membebani I/O harddisk. Mini-SIEM Anda menghitung skor risiko secara in-stream saat event masih di RAM dengan biaya komputasi mendekati nol.

4. Optimized Correlator (OC) Engine Design (Sensors MDPI 2024 / Jurnal 1)

Sumber: Sheeraz et al. (Sensors MDPI 2024 / PMC11314677: In-Memory Hyperscan Matching)
In-Memory SIMD Parallel
21x Lebih Cepat dari SEC & 2.5x Execution Efficiency INCIDENT SINK (MySQL) Hyperscan Match Callback Trigger alert event immediately Console Alert Dispatcher Real-time terminal reporting MySQL Relational Storage Post-detection archiving

Terobosan Riset Jurnal 1 MDPI

  • Membuktikan bahwa bottleneck utama sistem SIEM bukanlah database, melainkan kecepatan evaluasi pencocokan pola regex di mesin korelasi.
  • Mengganti sequential string parsing dengan parallel scan memangkas response time hingga 21 kali lipat.

Research Gap yang Kita Pecahkan

  • Hardware Lock-in: OC terikat pada CPU Intel dengan SIMD AVX2. Proyek Go Anda bersifat arsitektur-agnostik (jalan di ARM64, AMD64, Linux, Windows).
  • Proprietary Rules: OC memakai aturan regex C mentah. Proyek Anda mengadopsi Sigma YAML standar terbuka.

Integrasi Konsep ke Mini-SIEM Go

Prinsip pemecahan blok data dan evaluasi in-memory paralel diadopsi di Golang menggunakan Worker Pool Goroutines yang membaca event stream sebelum ditulis ke file persistensi alerts.json.

5. AutoSigma & ThreatPilot: Automated CTI-to-Rule Generation Pipeline

Sumber: Jurnal 4 (AutoSigma, arXiv 2026) & IntelEX / ThreatPilot (ACM / arXiv 2025)
Modern Detection-as-Code

Inovasi AutoSigma (Jurnal 4)

Membuktikan bahwa aturan deteksi tidak perlu lagi ditulis manual oleh analis manusia. Melalui grounding template repositori resmi Sigma HQ dan validasi ganda AI, aturan deteksi dapat dihasilkan secara otomatis dari laporan intelijen ancaman.

Keterkaitan Erat dengan Mini-SIEM Anda

AutoSigma hanya menghasilkan berkas rule.yaml tetapi tidak memiliki runtime engine mandiri. Di sinilah posisi kebaruan (*novelty*) TA Anda: membangun engine runtime Go yang langsung mengeksekusi berkas aturan Sigma tersebut secara real-time.

Integrasi Format Detection-as-Code

Menjadikan Mini-SIEM Anda kompatibel dengan ribuan aturan deteksi komunitas keamanan siber global tanpa harus menulis ulang logika deteksi di kode program.
