1. ALUR PENYERANGAN & LOG CAPTURE

Penyerang melancarkan serangan (Brute Force / SQLi) dari luar menuju port container target. Saat event terjadi:

  • Server 1 & 2 (Go): Middleware Go langsung menangkap kegagalan login secara non-blocking dan menembakkannya ke channel background.
  • RealKABIL (Laravel): Agent tailer membaca penambahan baris di storage/logs/laravel.log menggunakan inotify OS event.
  • Event dikirim seketika via HTTP POST JSON Stream ke siem-central:4000/api/v1/events.

2. PEMROSESAN IN-STREAM & PRE-STORAGE

Pusat SIEM memproses log 100% di memori RAM sebelum data ditulis ke penyimpanan:

  • Normalizer: Mengubah field acak menjadi struct seragam.
  • Upstream CTI: Mengecek cache IP di sync.Map; mendeteksi apakah IP berasal dari Datacenter Hosting atau Tor Exit Node (Jurnal 5).
  • Sliding Window: Memangkas timestamp kedaluwarsa (>5m) dan menghitung frekuensi kejadian tanpa batas fixed window (Jurnal 1 & 2).

3. EVALUASI ATURAN SIGMA & SKORING RBA

Mengevaluasi logika serangan menggunakan standar industri terbuka:

  • Membaca rule.yaml berbasis spesifikasi resmi Sigma HQ dan memetakan ke MITRE ATT&CK (T1110) (Jurnal 4).
  • Menghitung formula Risk-Based Alerting (RBA) berdasarkan keparahan aturan, akumulasi waktu, kelangkaan event, dan reputasi IP penyerang (Jurnal 13).

4. CLOSED-LOOP MITIGASI (SOAR) & UI

Siklus penuh respon insiden otonom sesuai NIST SP 800-61 Rev. 2:

  • Pencatatan Insiden: Insiden terkonfirmasi ditulis ke alerts.json sebagai bukti forensik digital (Jurnal 11).
  • Auto-Block Firewall: Perintah iptables -A INPUT -s <IP> -j DROP otomatis dikirim via Docker Socket ke container target untuk memutus serangan seketika.
  • Embedded Dashboard: Analis memantau live map dan grafik serangan di http://localhost:4000/dashboard (Single Binary Go).
